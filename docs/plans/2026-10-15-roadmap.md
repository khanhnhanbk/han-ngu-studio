## Shared hard rules (from CLAUDE.md)

- Deploys on the Vercel Hobby plan only. No paid features.
- No backend, API routes or database. Processing runs in the browser.
- User text is never sent anywhere. The only proposed exception is Phase 4a image search: opt-in, and it needs the owner's approval.
- Data is static (`public/data/`) and lazy-loaded on the page that needs it. Each file stays under about 1.5 MB raw.
- Python ports are faithful and covered by golden tests.
- UI text is Vietnamese and goes through `lib/i18n`.
- `npm test` and `npm run build` must pass before a phase is done.

## Source data (`assets/dictionary/`)

| File | Rows | Columns / notes |
|---|---|---|
| `char_hanviet.csv` | 11.2k | `simp_char,trad_char,hanviet,pinyin,frequency`. `hanviet` is a Python list literal (`['ngã']`). `pinyin` is TONE3 (`de5`, `nu:3`) or `*` |
| `chinese_dict.csv` | 10k | `Simplified,Traditional,W/million,Definitions,Pinyin` (CC-CEDICT English) |
| `sentences.tsv` | 4.6k | `idx,Hanzi,NewWord,Pinyin,Vietnamese,English,Lenth` |
| `100000sentences.csv` | 61.5k | `level,word,sentence,source`: Tatoeba sentences (CC BY 2.0 FR) per HSK word, Chinese only |
| `sentences_tatoeba_mt.tsv` | – | `tatoeba_id,hanzi,vi,en`: Google Translate output from `scripts/translate-sentences.mjs` |
| `word_list.txt` | 39k | Frequency list. Segmentation ships the 118k list in `public/data/word_list.txt` instead |

**pinyin-pro vs the data**: pinyin-pro `toneType:'num'` gives `de0` and `nü3`, while the data uses `de5` and `nu:3`. Normalise with `0→5` and `ü→u:`.
